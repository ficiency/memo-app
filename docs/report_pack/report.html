One memo engine: what it does, how we know, where it breaks

Luis Chapa9 Nov 2026FastAPI · Postgres (Supabase) · React · OpenAI

Each firm's memo format is stored as versioned data. A memo is built from that format and a deal's record, then edited in the browser, through an AI agent, or in PowerPoint and back. Every edit, from any of the three, goes through one server check before it lands, and nothing that cannot be applied is dropped: it is kept aside and shown. Three firms are loaded on one deal (Tidewell): Merrow (16:9 PowerPoint template), Corriemoor (4:3 template) and Lumen, the third firm, which sent only a written guide. Every number below comes from eval runs on the final code.

02Where the brief was silent: what we chose, and why

What says "same slide, same number"

A hidden identity in each shape's and slide's name, compared against the export the file came from. Titles, order and position change; the name survives PowerPoint saving the file (100% in the desktop suite).

What wins when two people and the record collide

One person holds a box at a time; others see who has it. Each box has a revision, so an edit made on an older view is kept aside instead of overwriting. A newer record never applies itself: it is announced live and applied by a person.

What each editor may change, and what goes to the record

Nobody edits a figure inside the memo; the record changes only by a new revision. A number typed over a figure is refused, not written back: a typo in a deck should not change the facts every memo and firm reads.

What checks the model

The same door that checks people. The model proposes, code validates (locked boxes, typed amounts, allowed sections), a person applies. No agent framework: one call per request with a context built by code.

How much freedom

The canvas exists only on free slides, inside the free area and on the grid. Every picture is a pending until someone confirms it, because a picture may be a chart pasted as an image.

The data model

Relational Postgres: memo → slide → box → paragraph → run, the same box model for layouts, slides and PowerPoint. History tables are only appended to (operations, conflicts, updates). A memo is read in one database round trip.

03How we know it works

The evals act as people do: their own server, the API the screens use, websockets like the canvas, real PowerPoint files. Expected outcomes come from each firm's rules, never its name, so one suite runs on all three. Where layout matters, Microsoft PowerPoint is the judge, not our own measure. To prove the suites catch failures, two faults were planted in the canvas suite (pictures exported 0.1 in off; figures allowed to be typed over): it dropped from 100% to 60% and named both.

04The third firm: configuration or code

All configuration. Lumen arrived with a guide only and went in through the same onboarding: 10 layouts with a generated master, 81 boxes, 9 text roles, 16 formats, 55 rules, 57 recipe segments, 38 figures, 4 table templates, 9 free areas. No line of code names a firm (0 hits across backend, scripts and evals). What it cost in code was generic: drawing boxes where there are no placeholders, generating a master. It also exposed one bug that hit every firm (tables with no column definitions were not measured), fixed for all.

05Where it breaks, and how often

45 issues were logged while building and testing, each with cause, area, severity and status. The evals found three of them late, all fixed at the root: tables without column definitions not measured, template bullets and indents lost, and a picture saved by PowerPoint desktop without an embedded image making the whole file be refused.

32 fixed2 partly fixed10 open1 not a bug

Weak today

  • highThe model binds a figure to a path of the right kind but sometimes the wrong datum (tenor shows 12 months, the deal is 36). Only the binding review by a person catches it.
  • medSome chart axes lack the firm's number format; onboarding can name chart series from their descriptions (fixed for Merrow only).
  • medPer-slide source lines and footnotes, and a risk matrix by probability × severity, still show "[no data]".
  • medA figure that is "some rows of a table" cannot be bound.
  • The 10 open issues come from earlier runs and were not re-confirmed on the final code.

Not tested

  • More than two people at once; disconnecting mid-edit (the memo reloads, missed messages are not replayed).
  • A person clicking in PowerPoint: the desktop suite drives PowerPoint through its automation interface.
  • Past memos' figures (their records were not given); Lumen rebuild (no past memos).
  • Load, and timings on anything but one laptop. Agent requests average 17–27 s per model call.

Not built

  • Continuing long text on another slide; promoting a slide into the template; template editing in the app; merging two people's typing in one box; Word output.
